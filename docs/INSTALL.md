# Установка BORZINI на Android

## Откуда взять APK

1. Откройте репозиторий на GitHub → вкладка **Actions**.
2. Выберите последний успешный запуск workflow **Android build** (зелёная галочка) для нужной
   ветки/коммита.
3. В разделе **Artifacts** внизу страницы запуска будет файл `borzini-debug-apk` (и
   `borzini-release-apk`, если настроен ключ подписи — см. `RELEASE_SIGNING.md`). Скачайте его —
   это ZIP-архив с одним файлом `app-debug.apk` (или `app-release.apk`) внутри.

## Какой это APK: тестовый или релизный

- **`app-debug.apk`** — тестовая (debug) сборка. Собирается всегда, автоматически при каждом
  пуше. Подписана временным debug-ключом Android — этого достаточно, чтобы установить и
  полноценно пользоваться приложением на своём телефоне, но для публикации в Google Play или
  распространения такой APK не предназначен.
- **`app-release.apk`** — релизная сборка. Появляется только если в репозиторий добавлены секреты
  подписи (`BORZINI_KEYSTORE_BASE64` и т.д., см. `RELEASE_SIGNING.md`). Это финальный вариант,
  готовый к реальному использованию и к будущим обновлениям без потери данных.

Пока вы не настроили свой ключ подписи, устанавливайте `app-debug.apk` — работает так же
полноценно, разница только в предназначении сборки.

## Установка на телефон/планшет

1. Скачайте `app-debug.apk` на устройство (или перенесите по USB/через облако).
2. В настройках Android разрешите установку приложений "из неизвестных источников" для того
   приложения, через которое открываете APK (обычно один раз запрашивается при первой установке).
3. Откройте APK-файл → **Установить**.
4. После установки на экране появится значок BORZINI — при запуске сразу открывается касса.

## Обновление приложения

Устанавливайте новый APK поверх старого (тем же способом) — идентификатор приложения
(`com.borzini.pos`) и ключ подписи одинаковы у всех сборок из одной ветки, поэтому Android
распознаёт установку как **обновление**, а не как новое приложение: вся база (склад, чеки,
рецептуры, настройки) сохраняется. Если Android пишет "не удалось установить, конфликт подписи" —
значит APK собран с другим ключом (например, debug вместо release или наоборот); в этом случае
нужно либо удалить старое приложение (потеряв данные — сначала сделайте резервную копию через
Настройки → «Резервное копирование»), либо переустанавливать сборки одного типа.

## Что нужно проверить и подтвердить самостоятельно

Я не устанавливал и не запускал APK на реальном или эмулированном Android-устройстве — рабочая
среда, где писался код, не может собрать Android-приложение локально (см. `README.md`), поэтому
я не подтверждаю работу собранного APK на устройстве как факт, а честно указываю: код написан,
бизнес-логика проверена юнит-тестами (`docs/QA_RESULTS.md`), но первый реальный запуск на
телефоне/планшете, вход в Google-аккаунт и сама установка — это шаг, который стоит выполнить вам
после того, как заберёте APK из GitHub Actions.
