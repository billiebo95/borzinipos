# Ключ подписи и релизные сборки

Чтобы обновления BORZINI ставились поверх старой версии без потери данных, **applicationId**
(`com.borzini.pos`) и **ключ подписи** должны оставаться одинаковыми во всех сборках, которые вы
устанавливаете как «одно и то же приложение». `applicationId` уже зафиксирован в
`app/build.gradle.kts` и менять его нельзя.

## Debug-сборка (по умолчанию)

Собирается всегда, подписывается временным debug-ключом Android (автоматически, для этого ничего
настраивать не нужно). Подходит для тестирования и повседневного использования, но лучше
перейти на свой ключ до того, как в базе накопится много реальных данных — debug-ключ одинаков у
всех разработчиков и не предназначен для боевого использования.

## Как создать свой релизный ключ

1. На своём компьютере (не обязательно в этой рабочей среде) выполните:
   ```
   keytool -genkeypair -v -keystore borzini-release.jks -alias borzini \
     -keyalg RSA -keysize 2048 -validity 10000
   ```
   Keytool спросит пароль хранилища, пароль ключа и данные владельца — придумайте пароли и
   сохраните их в надёжном месте (менеджер паролей). **Потеря этого файла или пароля означает,
   что вы больше никогда не сможете выпустить обновление под тем же приложением** — Android не
   разрешает переподписать существующее приложение другим ключом.

2. Никогда не добавляйте `.jks`-файл или пароли в Git — `.gitignore` уже исключает `*.jks` и
   `keystore.properties`.

3. Чтобы GitHub Actions мог подписывать релизные сборки, добавьте в репозиторий
   **Settings → Secrets and variables → Actions → New repository secret**:
   - `BORZINI_KEYSTORE_BASE64` — содержимое файла `borzini-release.jks`, закодированное в base64
     (`base64 -w0 borzini-release.jks`).
   - `BORZINI_KEYSTORE_PASSWORD` — пароль хранилища.
   - `BORZINI_KEY_ALIAS` — алиас ключа (в примере выше — `borzini`).
   - `BORZINI_KEY_PASSWORD` — пароль ключа.

   После этого воркфлоу `.github/workflows/android-build.yml` автоматически начнёт собирать и
   выкладывать `borzini-release-apk` при каждом пуше.

## Что я не сделал сам

Я не создавал за вас релизный keystore и не добавлял секреты в GitHub — это осознанное решение:
ключ подписи и его пароль должны быть только у вас, я не храню и не должен хранить такие секреты.
Пока секреты не добавлены, собирается и подтверждённо работает только debug-сборка.
