# Настройка Google Drive и Google Sheets для BORZINI

Это единственная часть, которую нельзя настроить без доступа к вашему Google-аккаунту — я
подготовил в коде всё, что можно сделать заранее (экран входа, создание папки и таблицы,
фоновую синхронизацию), но сам OAuth-клиент должен создать владелец Google-аккаунта.

Подключение Google Drive к этой сессии Claude (если оно у вас есть) **не даёт приложению BORZINI**
доступ к вашему аккаунту — это два независимых механизма. Android-приложению нужна собственная
авторизация через Google Cloud Console, шаги ниже.

## Шаг 1. Создайте проект в Google Cloud Console

1. Откройте https://console.cloud.google.com/ и войдите под тем Google-аккаунтом, который будет
   использоваться в кофейне.
2. Создайте новый проект (например, «BORZINI POS»).

## Шаг 2. Включите нужные API

В разделе **APIs & Services → Library** включите:

- **Google Drive API**
- **Google Sheets API**

## Шаг 3. Настройте экран согласия (OAuth consent screen)

1. **APIs & Services → OAuth consent screen**.
2. Тип пользователей: **External** (если это не аккаунт Google Workspace вашей организации) или
   **Internal** (если это Workspace-аккаунт кофейни).
3. Укажите название приложения «BORZINI», контактный email.
4. В разделе **Scopes** добавьте только: `.../auth/drive.file` (минимально необходимое
   разрешение — доступ только к файлам, созданным самим приложением, не ко всему Drive).
5. Пока приложение не прошло верификацию Google, аккаунты, под которыми вы будете входить, нужно
   добавить в список **Test users** на этом же экране.

## Шаг 4. Получите SHA-1 отпечаток сертификата приложения

Google требует привязать OAuth-клиент к конкретному отпечатку сертификата, которым подписан APK.

- **Для debug-сборки** (файл `app-debug.apk` из GitHub Actions) отпечаток стандартный для всех,
  кто использует Android-инструментарий с автогенерируемым debug-ключом:
  ```
  SHA1: 5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25
  ```
  Это публично известный отпечаток debug-хранилища Android (`~/.android/debug.keystore`),
  которое одинаково у всех разработчиков по умолчанию — им можно пользоваться для тестирования,
  но перед реальной работой кофейни настоятельно рекомендуется перейти на собственный релизный
  ключ (см. `RELEASE_SIGNING.md`) и получить SHA-1 именно от него.
- **Для релизного ключа** — после того как вы (или я, с вашего разрешения) создали keystore,
  выполните:
  ```
  keytool -list -v -keystore ваш_файл.jks -alias ваш_алиас
  ```
  и скопируйте строку `SHA1:` из вывода.

## Шаг 5. Создайте OAuth-клиент для Android

1. **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
2. Тип приложения: **Android**.
3. **Package name**: `com.borzini.pos`.
4. **SHA-1 certificate fingerprint**: значение из шага 4.
5. Сохраните. Отдельного «Client ID», который нужно было бы вписывать в код, для Android-варианта
   OAuth не требуется вручную — Google Play Services сам сопоставляет запрос приложения с этой
   записью по package name + SHA-1 на устройстве. Использованный в приложении scope —
   `drive.file` — уже зашит в код (`GoogleAuthManager.kt`).

## Шаг 6. Подключите аккаунт в приложении

1. Установите BORZINI на телефон/планшет (`docs/INSTALL.md`).
2. Откройте **Настройки → Google-аккаунт и синхронизация → Войти в Google-аккаунт**.
3. Выберите нужный аккаунт (или войдите). Если аккаунт не в списке **Test users** (шаг 3) —
   Google покажет предупреждение и не даст продолжить: добавьте его в список и повторите.
4. После входа нажмите **«Синхронизировать сейчас»** — приложение само создаст папку `BORZINI` на
   Google Drive и таблицу `BORZINI - данные` внутри неё, с листами: Категории, Товары, Склад,
   Закупки, Движения склада, Чеки, Возвраты, Расходы, Цели.

## Что я не смог проверить сам

Я не выполнял шаги 1–6 — они требуют вашего реального Google-аккаунта и физического или
эмулированного Android-устройства, которых нет в рабочей среде, где писался код. Код входа,
создания папки/таблицы и синхронизации написан и основан на официальных Drive v3 / Sheets v4 API,
но end-to-end поток (вход → создание таблицы → появление строк) не был прогнан вживую — 
проверьте его сами по шагам выше и напишите, если что-то пойдёт не так.
