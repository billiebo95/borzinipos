# Изменение схемы базы данных после релиза

`BorziniDatabase` сейчас на `version = 1`. Как только приложение с этой версией установлено хотя
бы у одного пользователя, менять существующие таблицы можно только через настоящую Room
`Migration`, никогда через `fallbackToDestructiveMigration()` — она стирает всю базу (весь склад
и все чеки) при обновлении.

Чек-лист при следующем изменении схемы:

1. Увеличьте `version` в `@Database(...)` в `BorziniDatabase.kt`.
2. Добавьте `Migration(oldVersion, newVersion)` с явным SQL (`ALTER TABLE ... ADD COLUMN ...` и
   т.п.) и зарегистрируйте её через `.addMigrations(...)` при создании базы в `AppContainer`.
3. Сравните экспортированную схему в `app/schemas/` (создаётся автоматически при сборке, см.
   `ksp { arg("room.schemaLocation", ...) }` в `app/build.gradle.kts`) до и после изменения —
   Room может сгенерировать тест на миграцию по этим файлам.
4. Резервная копия (`docs/BACKUP.md`) не привязана к номеру версии схемы Room напрямую, но несёт
   свой `formatVersion` (`BackupCodec`/`BackupRepository`) — если меняете набор полей сущности,
   обновите `BACKUP_FORMAT_VERSION` и код чтения старого формата, иначе старые резервные копии
   станет невозможно восстановить.
